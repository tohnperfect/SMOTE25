# Full extraction schema (SMOTE25 Data section, 18 Oct 2026)
One JSON object per paper. Two parts: (A) every dataset the paper uses, with its characteristics; (B) raw results of the proposed method vs plain SMOTE.

## Mandatory rules
- Copy every value EXACTLY as printed (keep decimals, keep typos in names). Never compute, never guess, never fill from your own knowledge of UCI/KEEL.
- If the paper does not print a value, use null. If the paper does not say something, write "not stated in paper".
- Every dataset row and every result table needs a source: "Table N, p.X" (PDF page index; add printed page if visible). If a table is an image or garbled in text extraction, download the PDF (mcp__Google_Drive__download_file_content), render that page in Bash (e.g. pdftoppm -r 200 -f X -l X) and read it visually; set is_image=true.
- Read supplementary files in the same Drive folder if the paper points to them (filename contains the method name and "Supplementary"). Do NOT fetch GitHub or web pages; if per-dataset results are only on GitHub/web, say so in notes with the URL as printed.
- Never decide winners.

## Part A: datasets
"datasets": [ {
  "name": "as printed (characteristics table if any, else results table, else text)",
  "group": "group/suite label in the paper, or ''",
  "source_repo": "UCI | KEEL | OpenML | imbalanced-learn | LibSVM | UCR | Kaggle | private | synthetic | other: <name> | not stated in paper",
  "n_instances": num|null, "n_features": num|null, "n_classes": num|null,
  "n_minority": num|null, "n_majority": num|null,
  "class_distribution": "as printed, e.g. '143/77/52' or null",
  "ir_printed": "as printed or null",
  "how_obtained": "original | repository-defined | modified | synthetic | not stated",
  "how_obtained_detail": "e.g. 'class 4 vs rest (stated in Table 2)', 'KEEL file yeast4 used as distributed', 'minority randomly undersampled to IR 50', '2-D Gaussians'",
  "in_results_table": "yes | no | not applicable (no per-dataset results)",
  "ref": "Table N, p.X"
} ]
how_obtained definitions:
- original: used as distributed and natively that number of classes (e.g. Pima, Haberman, a KEEL multiclass file), no class choice by authors.
- repository-defined: a two-class split made by the repository, used as is (KEEL names like yeast4, ecoli-0-1_vs_5, glass1; imbalanced-learn names like abalone_19, optical_digits).
- modified: the AUTHORS chose minority/majority classes, merged classes, set a threshold, dropped classes, undersampled, injected noise, or dropped attributes.
- synthetic: generated by the authors.
- not stated: the paper does not let you tell.

"ir_definition": "formula/wording or not stated in paper", "ir_definition_ref": "p.X",

## Part B: results vs SMOTE (copy raw numbers)
Choosing rule, in order:
1. Proposed method = the paper's main named method (abstract/conclusion variant if several; list others in notes).
2. SMOTE = plain original SMOTE as named in the paper (record name; multiclass papers may use e.g. 'SMOTE-all', 'SMOTE+OVO' - record exactly). Not Borderline-SMOTE/ADASYN.
3. Metric priority: G-mean > AUC > F-measure/F1 > accuracy (multiclass: MG/mGM = G-mean, MAUC = AUC, macro-F = F1). Highest-priority metric that has a per-dataset table with both methods.
4. Classifier: the one highlighted in the abstract, else the first reported. Fixed for the paper.
5. Condition: no added noise / original IR / main suite.
