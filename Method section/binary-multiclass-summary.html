What the matrix shows

  1. Most SMOTE-family generators are still two-class.

    23 of 37 are written for one minority class against the rest. Using them on multiclass data requires decomposition (one-vs-one, one-vs-rest) or reducing the data to two classes.

  2. What a method is designed for and what it was tested on are different questions.

    Loyalty-SMOTE has a binary rule but is run on multiclass data framed as largest class vs smallest class. 6 methods with a multiclass rule are never shown on two classes. QC-SMOTE states a one-vs-rest rule that it never runs, and KNNOR names one only as future work.

  3. Multiclass rules have become common only recently.

    Before 2018, 4 of 18 SMOTE-family methods have a multiclass rule; since 2018, 9 of 19 do.

  4. Binary-rule papers usually test on multiclass data reduced to two classes.

    17 of the 23 say they turned multiclass sources into two-class problems, usually the smallest class against the rest; the others use ready-made two-class benchmarks such as KEEL splits. (16 from the Method Map evidence text, Loyalty-SMOTE from its PDF.)

  5. "Multiclass" can come from outside the generator.

    In SMOTEBoost the classes are carried by AdaBoost.M2; its SMOTE step works on one minority class at a time with amounts set by hand.

The six edge cases checked against the PDFs

SMOTEBoostMulticlass rule

Several classes are handled by AdaBoost.M2, not by SMOTE: the formal algorithm names one minority class (Fig. 1, p.111), and in the 5-class KDDCup-99 run each minority class (U2R, R2L) gets a hand-set SMOTE amount (Sec. 4, p.112). Only U2R results are tabulated (Table 3).

INOSBinary rule

Written for a positive vs a negative class (Sec. 3, p.3). 48 two-class tasks built from 7 UCR sets, one class vs the rest (Sec. 4.2, pp.7-8); no multiclass extension mentioned.

KNNORBinary rule

Algorithms 1-2 split the data into Smin and Smaj (pp.4, 7). 19 KEEL two-class sets; image demos are also one class vs the rest. Per-class multiclass use is named only as future work (conclusion, p.16).

OREM / OREM-MMulticlass rule

OREM (Alg. 1) is two-class; OREM-M (Alg. 2, Sec. 3.2, p.6172) extends it: classes drawn in random order weighted by remaining quota, a synthetic point is dropped when its nearest neighbour is another minority class. OREM is tested on 28 two-class sets, OREM-M on 21 multiclass sets (never on two classes); OREMBoost on both.

Loyalty-SMOTEBinary rule

Loyalty and the Attraction relabelling use all classes, but SMOTE grows only one minority class (Sec. 3.3, p.6). The 5 multiclass sets are run as largest class vs smallest class and scored with binary metrics (Sec. 4.4.4, p.12). Earlier coded as native multiclass; corrected.

QC-SMOTEOne-vs-rest stated

Each underrepresented class is the target against all other classes (Sec. 3.1, p.4; Sec. 3.7, p.7), but all 30 datasets are binary (Sec. 4.1, Table 1); the multiclass rule is never run.
